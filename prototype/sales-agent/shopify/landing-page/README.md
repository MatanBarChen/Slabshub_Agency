# דף הנחיתה של הסוכן

דף עצמאי שאפשר לפרסם עליו מודעות: הגולש נוחת ישר על שיחה עם הסוכן, והסוכן מפנה אותו לחנות או לקלף ספציפי. שני דפים — עברי ואנגלי — מאותו קובץ סקשן.

## קבצים

| קובץ | תפקיד |
|---|---|
| `comics-chat.liquid` | הסקשן. מרנדר מסמך HTML שלם, דו-לשוני לפי הגדרת `lang` |
| `page.comics-chat.json` | תבנית עברית (`lang: he`) |
| `page.comics-chat-en.json` | תבנית אנגלית (`lang: en`) |
| `build_preview.py` | מרנדר את הסקשן ל-`preview-he.html` / `preview-en.html` |

## התקנה

כתיבת קבצי תמה חסומה מהסוכנות (ה-MCP מתיר כתיבה רק לתמות לא מפורסמות), אז ההדבקה ידנית בעורך של שופיפיי:

1. **Sections → Add a new section** בשם `comics-chat`, להדביק את `comics-chat.liquid`
2. **Templates → Add a new template** → סוג `page` → שם `comics-chat`, להדביק את `page.comics-chat.json`
3. אותו דבר לתבנית `comics-chat-en`
4. **Pages → Add page** ×2, ולבחור לכל אחד את התבנית שלו:
   - עברית → `/pages/chat`
   - אנגלית → `/pages/chat-en`

השמות חייבים להיות מדויקים. סניפט או תבנית בשם שלא תואם נכשלים בשקט בשופיפיי — בלי שגיאה ובלי תוכן.

## תצוגה מקדימה

```
py build_preview.py
```

`build_preview.py` לא מסיר תגי Liquid אלא **מריץ** את התת-קבוצה שהקובץ משתמש בה (`if/else`, `assign`, `for`, פילטרים). אם מישהו יוסיף לסקשן מבנה Liquid שהוא לא מכיר — הוא זורק שגיאה במקום לרנדר משהו שנראה תקין אבל שונה ממה שהחנות תציג.

להגיש דרך `localhost` (למשל `py -m http.server 8765` מהשורש), **לא** לפתוח מהדיסק — מקור `file://` נחסם על ידי הפונקציה.

## כרטיסי מוצר

כשהסוכן ממליץ על קלף, מופיע כרטיס עם שם, מחיר, תג "יחיד במלאי" ותמונה.

**מה שומר על חוקי האמת:** כרטיס נבנה רק למוצר שה-URL שלו מופיע בפועל בטקסט שהסוכן כתב, והנתונים מגיעים מפלט `search_catalog` — לא מניחוש בדפדפן. מוצר שהסוכן מצא אבל בחר לא להמליץ עליו לא יקבל כרטיס.

הדפדפן זוכר מוצרים **מכל השיחה**, לא רק מהתור הנוכחי. הסוכן מזכיר קלף שמצא לפני כמה תורות בלי לחפש שוב, ובתור כזה אין `trace` — התאמה מול התור הנוכחי בלבד הייתה מפילה את הכרטיס בדיוק כשהוא ממליץ.

שורת URL שקיבלה כרטיס נמחקת מהטקסט, אחרת הלינק מופיע פעמיים. URL באמצע משפט נשאר במקומו והופך ללינק רגיל.

**התמונה** נמשכת מ-`/products/<handle>.js` של שופיפיי ולא מסנפשוט הקטלוג — נתון חי שלא מתיישן. בתצוגה מקדימה מקומית זה נכשל (דומיין אחר) והכרטיס פשוט נשאר בלי תמונה, בלי חור בפריסה.

## ייחוס

מודעה ששולחת לדף מגיעה עם UTM משלה. הצ'אט **לא דורס אותה** — הקמפיין הנכנס עובר כמו שהוא ללינקי המוצר, והצ'אט מסמן את עצמו רק ב-`utm_content=chat-agent`. ביקור ישיר מקבל `utm_source=chat-agent`. פירוט ב-`docs/utm-convention.md`.

## עלות

כל הודעה עולה טוקנים, ודף שמפרסמים עליו חשוף יותר מווידג'ט בפינה. ההגנות בפונקציה: 40 הודעות לשעה ל-IP, 60 תורות לשיחה, 2000 תווים להודעה, ורשימת מקורות מותרים.

**עוד אין תקרה יומית גלובלית.** לפני שמעלים מודעות בתקציב, כדאי להוסיף אחת — יום חריג ייעצר מעצמו במקום להפתיע בחשבון.

## מה נבדק (2026-08-31)

מול הפונקציה החיה מ-`localhost`: כרטיסים נבנים ותואמים למה שהסוכן המליץ, UTM נכון על כל לינק, שורות URL כפולות נמחקות, כרטיס שורד תור שבו הסוכן ענה מהזיכרון, שתי השפות מרנדרות בכיוון הנכון, ומובייל ב-375px בלי גלילה אופקית.

שאלת מלכודת ("כמה שווה הקלף שלי ומה יהיה בעוד 5 שנים") — הסוכן סירב להערכת שווי ולתחזית, הפנה לגורם מתאים, וחזר לעזור לבחור. זה הסיכון המרכזי בדף שמבטיח "שאל כל דבר", והוא מטופל בקופי: הכותרת מבטיחה קלפים, ציונים, סטים ומלאי — לא הערכות שווי.
